# Meeting Note Templates

Reusable templates for the meeting types CSE 110 requires. Copy the
relevant file, rename it per the convention below, and fill it in.

## Templates

| Template                                                             | When to use                                  | Save copy to                                                                                   |
| -------------------------------------------------------------------- | -------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| [`sprint-planning.md`](./sprint-planning.md)                         | Before starting work each sprint             | `docs/meetings/sprint-planning/sprint-<N>-planning-YYYY-MM-DD.md`                              |
| [`standup.md`](./standup.md)                                         | Each standup (≥ 3× per week)                 | `docs/meetings/standups/standup-YYYY-MM-DD.md`                                                 |
| [`sprint-review-retrospective.md`](./sprint-review-retrospective.md) | End of each sprint (≥ 2 total this quarter)  | `docs/meetings/retrospectives/sprint-<N>-retro-YYYY-MM-DD.md`                                  |
| [`ta-meeting.md`](./ta-meeting.md)                                   | Weekly TA meeting (and the ≥ 1 Prof meeting) | `docs/meetings/ta/ta-meeting-YYYY-MM-DD.md` (or `docs/meetings/prof/...` for the Prof meeting) |

## Naming Convention

- Always use **`YYYY-MM-DD`** for dates (sorts chronologically).
- Use kebab-case for filenames.
- For sprint-scoped files, include the sprint number: `sprint-1-...`.

## CSE 110 Requirements These Cover

- Sprint planning meeting documented before each sprint.
- Standups captured ≥ 3× per week.
- Sprint review + retrospective at least 2× in the remaining quarter,
  with evidence of incorporation.
- Weekly TA meeting captured.
- At least one Prof meeting before the end of the quarter.

If a meeting doesn't fit one of these templates, prefer adapting the
closest one over inventing a new format — consistency makes the repo
easier to grade and easier to navigate.
